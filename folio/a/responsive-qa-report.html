What the suite prevents

  • Feature text overlapping or hiding the active image.
  • Section labels colliding with feature titles.
  • Images shrinking into a narrow sliver or disappearing.
  • Mobile artwork being cropped to fill the gallery instead of preserving the full composition.
  • Captions leaving the visible viewport.
  • Horizontal document overflow.
  • Lazy-loaded images being treated as ready before they decode.

How the protection works

  1. Playwright opens the site in three independent rendering engines.
  2. Each project and frame is activated at two portrait sizes and two font scales.
  3. Geometry assertions measure the page, verifying that narrative, image and caption regions do not collide or escape the viewport.
  4. Failure evidence is retained as a screenshot and execution trace.
  5. A tracked Git pre-push hook runs the suite before deployment changes can leave the machine.
  6. A GitHub Actions workflow repeats the suite when cloud runners are available.

Run the report suite

From the portfolio source directory:

qa-mobile.cmd

Or run the underlying commands:

cd qa
npm ci
npx playwright install chromium firefox webkit
npm test

Where the implementation lives

qa/tests/mobile-layout.spec.mjs contains the assertions. qa/playwright.config.mjs defines engines, retries and failure artifacts. .githooks/pre-push enforces the local gate.

Known limits

Automated rendering engines catch layout regressions consistently, but they are not a complete substitute for physical-device checks. Android Chrome and Firefox may apply manufacturer-specific font scaling, browser chrome and safe-area behavior. A short real-device smoke test remains appropriate before major visual releases.
